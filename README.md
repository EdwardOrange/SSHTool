# SSH 运维终端

面向 Linux 服务器日常运维的 Windows 桌面 SSH 客户端，将交互式终端、资源监控、防火墙规则管理、SFTP 文件管理和端口转发集中在一个 Material Design 界面中。

项目采用 **Tauri 2 + React 19 + TypeScript + Rust**，通过 SSH 连接远程服务器，无需在服务器上安装专用常驻代理。服务器配置、操作记录和监控历史保存在本机，选择记住的密码与私钥口令交由 Windows Credential Manager 保存。

当前版本：`0.1.0`。桌面构建以 Windows 为目标；浏览器模式可用于界面预览，使用演示数据。

## 环境要求

### 本地开发环境

以下步骤以 Windows 上的 PowerShell 为例。

| 依赖 | 要求或用途 |
| --- | --- |
| Node.js 与 npm | 当前 Vite 依赖要求 Node.js `^20.19.0` 或 `>=22.12.0`；npm 用于安装前端依赖和运行脚本 |
| Rust 与 Cargo | 使用支持 Rust 2024 edition 的 stable MSVC 工具链；仓库未固定最低 Rust 版本，依赖可能要求更新的编译器 |
| Microsoft C++ Build Tools | 安装“使用 C++ 的桌面开发”工作负载及 Windows SDK，用于编译 Rust 桌面程序与原生依赖 |
| Microsoft Edge WebView2 Runtime | 桌面界面的运行时依赖；运行构建好的 EXE 也需要 |

Windows 的 C++、WebView2 和 MSVC 工具链安装方式见 [Tauri 官方环境准备文档](https://v2.tauri.app/start/prerequisites/#windows)。仅预览浏览器界面时，只需 Node.js 与 npm。

在项目根目录检查工具是否可用：

```powershell
node --version
npm --version
rustc --version
cargo --version
```

### 远程服务器

| 功能 | 远程条件 |
| --- | --- |
| SSH 终端 | 可访问的 SSH 服务、有效账号和交互式 Shell |
| SFTP | SSH 服务启用 SFTP 子系统，账号对目标路径有相应读写权限 |
| 资源监控 | Linux `/proc`，以及 `sh`、`head`、`grep`、`cat`、`cut`、`df`、`tail`、`ss`、`ps` 等命令；采集脚本使用 GNU/Linux 常见参数 |
| 终端命令记录 | Bash 或 Zsh，以及 `base64`；通过当前 Shell 的钩子获取已执行命令和退出状态 |
| 防火墙管理 | 已安装对应防火墙工具，并具备 root 或适当的 sudo 权限；写入还要求可靠的回滚调度机制 |
| 端口转发 | SSH 服务允许对应类型的 TCP 转发，目标地址可从相应一侧访问 |

这些条件按功能分别生效。例如，服务器没有 `ss` 会影响资源监控，但不代表无法使用 SSH 终端。

## 快速开始

### 启动桌面开发版

获取仓库代码并进入项目根目录后执行：

```powershell
npm ci
npm run desktop:dev
```

`npm ci` 按 `package-lock.json` 安装依赖。桌面开发命令会自动启动 Vite，再编译并打开 Tauri 窗口，无需另外运行 `npm run dev`。首次启动需要下载 Rust 依赖并编译，耗时通常长于后续启动。

### 仅预览浏览器界面

```powershell
npm ci
npm run dev
```

打开 [本地预览页面](http://localhost:1420)。应用在非 Tauri 环境下自动使用模拟服务器、指标和操作结果，**不会建立真实 SSH 连接**。演示状态主要保存在内存中，刷新后可能重置；原生文件选择、配置导入导出等能力应在桌面版中验证。

开发端口固定为 `1420`，且启用了 `strictPort`。若端口被占用，Vite 会报错退出，不会自动切换端口。

### 运行已构建程序

完成[桌面构建](#构建与测试)后，可使用生成的 MSI 安装包，或直接运行 `src-tauri/target/release/ssh-operations-terminal.exe`。运行成品无需 Node.js、Rust 或源码，但仍需 WebView2 Runtime。

直接运行 EXE 时，应用仍把数据写入当前 Windows 用户的应用数据目录，并非将全部数据保存在 EXE 旁边的便携模式。

## 使用指南

### 1. 添加服务器并建立连接

1. 在服务器列表中新增服务器，填写显示名称、主机名或 IP、SSH 端口和用户名。
2. 选择认证方式，按需填写密码、私钥路径和私钥口令。
3. 可设置分组、逗号分隔的标签及收藏状态，然后保存。
4. 连接服务器；未保存的密码或必要的私钥口令会在连接过程中询问。
5. 首次连接时核对主机密钥指纹，确认后建立信任。

| 认证方式 | 使用说明 |
| --- | --- |
| 密码 | 可在连接时输入，或选择保存到 Windows Credential Manager |
| 私钥 | 填写本机私钥文件路径；加密私钥需要口令，可选择安全保存口令 |
| SSH Agent | 使用 Windows SSH Agent 中已加载的密钥；默认连接 `\\.\pipe\openssh-ssh-agent`，可由 `SSH_AUTH_SOCK` 指定命名管道 |
| 键盘交互 | 使用一次输入的响应进行认证；不支持需要不同答案的多步 MFA |

已连接服务器的地址、认证方式或跳板配置发生变化前，需要先断开连接。更换连接身份后，应重新提供凭据。主机密钥与已保存记录不一致时连接会被拒绝，应先确认远程主机身份和密钥变化原因。

### 2. 使用终端

连接后进入“终端”页即可操作远程 Shell。终端会随视图尺寸调整，并提供内容搜索和选中复制；选中内容后可用 `Ctrl+Shift+C` 复制。

终端字号、回滚缓冲行数、粘贴保护和命令记录开关可在设置中调整。命令记录依赖 Bash／Zsh 钩子，记录命令与退出码，不保存完整终端输出，也不是按键录制或会话录像。未支持的 Shell 或钩子初始化失败时，终端会提示记录不可用。

### 3. 查看资源监控

“监控”页通过 SSH 周期执行采集命令，无需额外部署监控代理。

- 查看 CPU、内存、根分区磁盘、负载、网络收发速率及运行时间。
- 查看网络连接与 CPU 使用率靠前的进程；连接详情最多采集 200 条，进程最多 10 条。
- 在设置中选择 `2`、`5`、`10` 或 `30` 秒的采样间隔，默认 `2` 秒。
- 查询本地已采集的历史数据；程序未运行或没有采集期间不会补齐历史。

CPU 和网络速率根据相邻样本差值计算，刚开始采集时需要建立基线。磁盘指标针对根分区 `/`，不是所有挂载点的汇总。

### 4. 管理防火墙

防火墙写入采用“生成计划 → 确认执行 → 验证连接 → 保留更改”的流程。

1. 打开“防火墙”页，读取后端、当前规则和回滚能力；需要时输入 sudo 密码。
2. 添加规则或删除可编辑规则，生成变更计划。
3. 检查将执行的命令、风险提示及当前状态，再确认执行。
4. 应用在变更前保存快照，并安排服务器端自动回滚；执行时会校验状态，避免使用过期计划。
5. 应用后会尝试建立新的 SSH 连接进行验证。在界面显示的截止时间前点击“保留更改”，也可以选择“立即回滚”。未确认保留时，服务器端任务将执行回滚。

自动回滚窗口为 **60 秒**，以界面返回的截止时间为准。写入要求服务器具备 `flock`，以及可用的 `systemd-run` 或 `at`（`atd` 正在运行）。缺少可靠回滚机制时，界面禁用写入。

**后端边界：** UFW 和 firewalld 支持受约束的规则变更；复杂或无法安全映射的规则可能标记为只读。nftables 当前禁止写入，不应将后端识别能力理解为完整规则编辑支持。若回滚截止时间已过，需刷新状态确认实际结果。

### 5. 管理文件与传输

在“文件管理”页浏览远程目录，可上传或下载文件与目录、新建目录、重命名、删除及复制远程文件。传输抽屉显示任务进度，并允许取消任务。

目标已存在时，支持询问、覆盖、跳过、重命名和续传。续传会先校验已有内容，发现不一致时终止，避免将不同文件拼接。递归传输不会跟随符号链接，不适合作为保留全部链接语义的文件系统备份工具。

文件操作使用当前 SSH 账号的权限；防火墙页输入的 sudo 密码不会使 SFTP 自动获得提权权限。

### 6. 配置端口转发

进入“端口转发”页新增配置，填写监听地址、端口及必要的目标地址，然后启动。

| 类型 | 监听位置与流向 | 示例 |
| --- | --- | --- |
| 本地转发 | 本机监听，经 SSH 服务器访问目标 | 本机 `127.0.0.1:15432` → 服务器可访问的 `127.0.0.1:5432` |
| 远程转发 | SSH 服务器监听，经隧道访问本机一侧目标 | 服务器 `127.0.0.1:18080` → 本机 `127.0.0.1:3000` |
| 动态转发 | 本机提供 SOCKS5 入口，经 SSH 服务器访问请求目标 | 本机 `127.0.0.1:1080` 作为 SOCKS5 代理 |

本地转发的目标地址从服务器一侧解析，远程转发的目标从客户端一侧访问。默认监听地址为 `127.0.0.1`；改为其他地址会改变可访问范围。远程监听还受 SSH 服务端配置约束。动态转发当前用于 SOCKS5 CONNECT TCP 请求，不提供 UDP 转发。

### 7. 查看命令记录

底部命令记录台汇总各模块的操作，可按来源筛选、搜索命令和输出、展开详情、复制、导出或永久清空。

- 后台命令在有返回数据时记录输出、错误、退出码和耗时。
- SFTP 等协议操作可能以等价命令描述展示，不代表实际启动了该命令行工具。
- 默认降噪规则隐藏监控采样记录；隐藏仅影响展示和当前筛选导出，不会停止采样或阻止记录入库。
- 历史读取最多返回最近 2,000 条，面板显示筛选结果中的最近 100 条。界面导出基于已加载、已筛选记录，不是整个数据库的备份。

### 8. 导入与导出服务器配置

通过界面的导入／导出入口读写 JSON 服务器配置。导出不包含密码、私钥内容或凭据引用，也不包含命令历史、监控历史和完整应用设置。

导入会清除凭据引用与导入的主机信任信息，新导入的服务器需重新提供认证信息并确认指纹。相同服务器 ID 已存在时会跳过，不覆盖现有配置。私钥路径仍是原机器的路径，迁移后需检查并调整。

## 设置与数据存储

### 默认设置

| 设置 | 默认值 |
| --- | --- |
| 语言／主题 | 中文／跟随系统 |
| 默认页面 | 监控 |
| 终端字号／回滚缓冲 | 13 px／10,000 行 |
| 粘贴保护／终端命令记录 | 开启／开启 |
| 监控间隔 | 2 秒 |
| 传输冲突策略 | 询问 |
| 命令记录保留 | 7 天、记录数据量上限 100 MiB |
| 默认降噪 | 隐藏监控采样操作 |

设置会保存到本地数据库。命令历史在写入新记录时按时间和容量清理；容量限制针对记录数据量，不等同于 SQLite 文件的物理大小。

### 本地存储位置

Windows 上的数据库默认位于：

```text
%APPDATA%\com.sshoperations.terminal\ssh-operations.db
```

| 数据 | 存储方式 |
| --- | --- |
| 服务器、可信主机指纹、转发配置、设置、命令与监控历史 | 本地 SQLite 数据库 |
| 选择记住的 SSH 密码、私钥口令和 sudo 密码 | Windows Credential Manager，服务标识为 `com.sshoperations.terminal` |
| 私钥文件 | 保留在用户指定的路径，应用按路径读取 |
| 部分启动与界面偏好 | WebView 本地存储缓存，数据库中的应用设置为准 |

监控原始样本保留约 1 小时；每分钟保留一个最新观测样本用于 24 小时历史，每 5 分钟保留一个最新样本用于 7 天历史。这些是降采样点，不是区间平均值。

备份本地数据前应完全退出应用，再复制应用数据目录。数据库备份不包含 Credential Manager 中的秘密或外部私钥，跨机器迁移后通常需要重新配置凭据。

### 记录与凭据边界

命令及输出在保存和广播前会对常见的 `password`、`token`、`secret`、`api_key`、`Authorization` 等形式脱敏。脱敏是模式匹配，不保证识别任意自定义格式中的秘密。SQLite 数据库本身没有应用层加密，配置和记录仍可能包含主机地址、用户名、路径及业务输出，分享导出文件前需检查内容。

## 构建与测试

所有命令均在项目根目录执行。

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动浏览器演示与前端开发服务器 |
| `npm run desktop:dev` | 启动 Tauri 桌面开发版 |
| `npm run test` | 运行 Vitest 前端测试 |
| `npm run test:watch` | 以监听模式运行前端测试 |
| `npm run build` | 执行 TypeScript 检查并构建前端 |
| `cargo test --locked --manifest-path src-tauri/Cargo.toml` | 运行默认 Rust 测试，不执行标记为 ignored 的真实服务器测试 |
| `npm run desktop:build` | 先构建前端，再编译桌面程序并生成 MSI |
| `npm run tauri -- --help` | 查看 Tauri CLI 帮助 |

发布前可依次执行：

```powershell
npm ci
npm run test
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run desktop:build
```

`desktop:build` 已通过 `beforeBuildCommand` 包含 `npm run build`，无需为打包重复运行前端构建。当前配置只生成 MSI 安装包，并配置了中文和英文安装语言。

默认产物路径如下；设置 `CARGO_TARGET_DIR` 等构建选项时路径会相应变化：

```text
dist/                                                  # 前端静态资源
src-tauri/target/release/ssh-operations-terminal.exe    # 桌面可执行文件
src-tauri/target/release/bundle/msi/                    # MSI 安装包
```

### 真实服务器集成测试

`src-tauri/src/live_ssh_tests.rs` 和 `src-tauri/src/live_firewall_tests.rs` 包含默认忽略的实机测试。它们需要显式设置 `SSHOPS_LIVE_TEST=1`，并依赖已保存、已信任的服务器及测试夹具要求。

SSH 实机测试可通过 `SSHOPS_LIVE_DB` 指定数据库、`SSHOPS_LIVE_HOST_NAME` 选择已保存主机，通过 `SSHOPS_LIVE_SCOPE` 缩小范围。防火墙测试有独立的服务器选择逻辑。运行前应阅读对应测试文件，并仅在明确用于测试的服务器上执行：这些测试会创建远程测试目录、建立转发，防火墙测试还会实际修改规则并验证回滚。

仓库根目录的 `DEEP_REVIEW*.md`、`REVIEW.md` 和 `LIVE_VALIDATION_2026-09-20.md` 保存了历史审查或实机验证记录；它们反映对应时间的检查结果，不替代当前版本的测试。

## 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 界面出现“演示数据”，操作没有影响服务器 | 当前是浏览器模式；使用 `npm run desktop:dev` 或构建后的桌面程序 |
| 开发启动提示端口被占用 | 检查 `1420` 是否已有 Vite 实例；桌面开发命令本身会启动 Vite。若确需改端口，同时修改 `vite.config.ts` 和 `tauri.conf.json` 中的 `devUrl` |
| PowerShell 阻止执行 `npm.ps1` | 可使用 `npm.cmd ci`、`npm.cmd run desktop:dev` 等对应命令 |
| 缺少 `cargo`、链接器或 Windows SDK | 检查 Rust MSVC 工具链和 C++ 桌面开发工作负载，安装后重新打开终端 |
| Rust 编译提示语法或编译器版本不支持 | 更新 stable MSVC 工具链，再按锁文件构建；项目使用 Rust 2024 edition |
| 桌面窗口无法正常加载 | 检查 WebView2 Runtime；开发模式还需确认 Vite 在 `1420` 正常启动 |
| MSI 构建出现 `light.exe` 错误 | 按 [Tauri 的 MSI 前置条件说明](https://v2.tauri.app/start/prerequisites/#vbscript-for-msi-installers) 检查 Windows VBSCRIPT 可选功能 |
| SSH 认证失败 | 核对用户名、认证方式、私钥路径或口令；使用 Agent 时确认服务可用且已加载密钥 |
| SSH 主机密钥不匹配 | 先通过可信渠道核对服务器指纹，确认是否重装、换机或更换了密钥 |
| 监控报错或没有数据 | 检查远程 `/proc`、`ss`、`ps` 等命令及权限；网络和 CPU 差值需等待后续样本 |
| 防火墙“添加规则”不可用 | 检查防火墙后端、sudo 权限、`flock` 和回滚调度器；nftables 当前只读 |
| SFTP 报权限错误 | 检查远程目录权限和 SFTP 子系统；文件操作不自动使用 sudo |
| 续传提示内容不一致 | 源文件与已有目标前缀不同；核实目标后重新选择覆盖或重命名策略 |
| 转发无法启动或无法访问 | 检查端口占用、目标地址所在一侧的可达性，以及服务端 TCP 转发策略 |
| 终端命令未出现在记录台 | 检查记录开关、Shell 支持及钩子提示，也检查筛选和降噪规则；记录通常在命令结束并返回提示符后产生 |

## 当前限制

- **平台：** 当前打包目标是 Windows MSI，凭据后端启用 Windows 原生实现，SSH Agent 仅实现 Windows 分支；不承诺 macOS／Linux 桌面版可直接构建使用。
- **远程系统：** 资源监控针对 Linux；其他系统即使能使用 SSH，也不代表监控和防火墙功能兼容。
- **认证与跳板：** 多步 MFA 尚不支持。后端具有跳板连接相关数据结构与逻辑，但当前新增／编辑服务器对话框没有跳板链配置入口。
- **防火墙：** nftables 禁止写入，复杂规则可能只读；当前界面主要提供规则新增与删除，不是完整防火墙控制台。
- **命令记录：** 终端记录依赖 Shell 协作，不覆盖所有交互程序输入、嵌套环境或完整输出，不应作为不可绕过的服务端审计系统。
- **国际化：** 提供中文和英文切换，但部分功能说明与错误信息仍为中文。

## 开发与贡献

修改前先确认涉及的前端视图、`src/api.ts` 中的 IPC 封装以及 Rust 对应命令。涉及数据模型或设置的修改，应同步检查 TypeScript 和 Rust 类型、默认值、持久化兼容性与浏览器演示实现。

提交变更时，请说明复现方式、改动行为和验证结果；按改动范围运行前端测试、Rust 测试及构建。SSH、SFTP、防火墙与转发的实机行为还需在测试服务器上验证。不要提交真实凭据、私钥、数据库、环境变量文件或包含秘密的调试输出。
